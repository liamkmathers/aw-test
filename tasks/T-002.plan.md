## Decisions

- **`shell: bash` on the pr.yml typecheck step.** The 0.1.2 `github/pr.yml` template carries it on the `__TYPECHECK__` step; the current repo file has no `shell:` key on any step. On `ubuntu-latest` the default is already `bash -e`, so this is a no-op today — I am including it to match the template and avoid re-drifting. Say so and I will drop it; the acceptance criterion does not require it.
- **The rest of pr.yml is already correct.** Every other line differs from the template only because the template's `__PM__`/`__INSTALL__`/`__SRC_DIRS__`/`__TEST_REGEX__` placeholders are already rendered in this repo. Nothing else to sync.
- **`docs/wiki/` needs no change.** Nothing in it describes the typecheck command or the workflow section — confirmed before commit 2: `docs/wiki/` holds only `README.md`, `INDEX.md`, `_decision.md`, `_module.md`, and none of them mention `tsc`, `typecheck`, `assess`, or `prettier`.
- **Added `.prettierignore` (departure from the approved plan, approved mid-task).** The plugin's `PostToolUse` hook `scripts/format-changed.sh` runs `prettier --write` on every `.md` file edited with Write/Edit — which workflow rule 6 now mandates — but the templates the plugin ships are not prettier-clean. Prettier adds a blank line after every heading and collapses the frontmatter alignment spaces (`kind: feature        #` → `kind: feature #`), so any tool edit to `CLAUDE.md`, `REVIEW.md`, or `tasks/TEMPLATE.md` made a byte-exact template match unreachable. The repo's pre-existing copies escaped this only because `/init-workflow` wrote them with a script. Ignoring these paths keeps them verbatim and stops them re-drifting on every future edit. Verified prettier honours the ignore file even for explicitly-named paths.

  Scope note: the committed pattern is `CLAUDE.md`, `REVIEW.md`, and `tasks/*.md`. That last glob is broader than the three files the criteria name — it ignores every `.md` directly under `tasks/`, so `INDEX.md`, `T-001.md`, `T-002.md` and this plan are unformatted too. That is deliberate, not accidental: task files inherit `TEMPLATE.md`'s frontmatter alignment (`kind: feature        # ...`), which prettier collapses, and it reflowed this plan's headings before the ignore file existed. The glob is non-recursive, so nothing under `tasks/` subdirectories is affected.
- **Committed `tasks/INDEX.md`.** Generated by the plugin's `task-index.sh` hook; it appeared untracked when `tasks/T-002.md` was created and must list T-002 to be truthful. Committing it keeps the tree clean for the "clean tree" criterion.
