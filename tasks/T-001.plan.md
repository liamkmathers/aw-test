## Risks
The riskiest step is 5, and it is the one honest gap in this plan: the committed test does not
make a real HTTP request, so it verifies "GET /about returns 200" by proxy (route file present
+ component renders) rather than directly. A direct test would need either a built server
booted in a global setup or supertest-style infrastructure; both add dependencies and files
beyond the task's expected set and add ~30-60s to every CI run, for a static page whose 200 is
a function of file placement. Step 5 closes the gap once, by hand.

Otherwise low risk: two new files, no existing file touched, no shared surface. `next build`
in step 5 writes `.next/` — already gitignored, confirm before committing.

Second-order: `docs/wiki/` has no page that adding a route makes false (only templates and a
generated, currently empty INDEX). No wiki edit is due. The step-5 trade-off above is arguably
a "why" decision worth a `/decide` page; flagged rather than done, since it is one line of
scaffolding policy and outside this task.
